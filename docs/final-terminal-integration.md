# Terminal integration follow-up

This resolves the pager, pending-input and startup diagnostics handoffs in [the terminal audit](final-terminal.md) and [the configuration workflow review](final-config.md). It was exercised on the simulator without an IOS image or a physical device.

| Repro | Result |
| --- | --- |
| `alias exec lp terminal length 0` → `lp` (or `do lp`) → `show running-config` | No `--More--`. CLI outcomes, Lab session views and the workbench all use the session's actual length. `terminal no length` restores the opening line default and a successful reload starts from the saved line default. The UI setting can turn paging off independently. At `--More--`, Space advances a page, Enter advances a line, and Q, Escape or Ctrl-C/Ctrl-Z stops; ordinary keys are not sent as input to the CLI. |
| Type `?` or Tab while entering a banner, username, password, or confirmation | `?` is ordinary text there; Tab does not invoke completion or change the reply. History stays unavailable while answering a pending prompt. The API reports command vs. text/confirmation/password without exposing handler data. Bulk paste stops before manual replies, even those with no visible prompt. The initial setup skip and copy destination still support pasted answers (including blank default destinations). |
| Paste `enable 1` followed by another command, or paste `show running-config` when a banner contains `% Invalid input …` | Actual command status stops the first paste; the second paste continues because `show` succeeded. Guide denials and closed sessions also stop the queue. Only older mock views without a status use the old diagnostic fallback; missing mock length means 24, not inferred from command text. Unfamiliar legacy prompts are manual. |
| Define an alias for a credential command and enter an argument (or use an alias containing a credential) | The same single alias resolution is used to classify the input before display or journaling. The workbench labels a masked echo as workbench redaction, not device output or a command ready to paste; login password replies are not echoed at all. Supported credential aliases do not expose their arguments in input preview, history, guide denials, journal, help, or `show aliases`. |
| A saved lab contains an unrecognized startup line or unsupported credential | `copy startup-config running-config` and `reload` validate on a copy. They report each failing source line number and diagnostic without replaying the saved line, say which operation was canceled, and keep running/startup configuration and open sessions unchanged. A successful reload still ends Telnet and applies the saved configuration; the configuration editor's ordinary file merge still keeps successful lines on error. |

## Evidence and limits

- `node --test --test-concurrency=4 tests/cli/{final-terminal,base-exec,base-system,framework,crypto-commands,execnet-ping,nat-cli}.test.ts tests/config/{apply,showconfig}.test.ts tests/lab/{terminal-ui,console,files,progress,persistence}.test.ts` — **160 passed**, including new framework and real Lab/Workbench terminal-model cases and an imported-startup regression that keeps both console and Telnet alive after a rejected reload.
- `npm run typecheck` and `./node_modules/.bin/vite build --outDir /tmp/pagerwing-build --emptyOutDir` — passed; no artifacts were published.
- These tests exercise terminal behavior and safe presentation data in Node, not physical console hardware or browser keyboard/IME behavior. The Workbench still buffers whole lines; its output pager is local UI state. Command status records CLI acceptance, not whether a network check succeeded.
- This is masking for recognized lab credential commands and login prompts, not a secret scanner. Explicit configuration output, configuration editors, exported device state, and freeform text can still carry lab-only values. Restored old journal entries whose aliases were removed/redefined may be unclassifiable; current journals are masked when entered.
