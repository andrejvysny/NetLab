# EXAM forwarding audit

This is a deterministic teaching model, not IOS XE emulation or a hardware test. The reference case uses R1 LAN ingress ACL → route → static NAT (PC1) or PAT (PC2) → crypto selection → WAN ACL/QoS. R2 sees PC1 at `60.50.50.100` (R1 Loopback100) for Telnet and SNMP. In the other direction, R1 unwraps modeled ESP and applies outside-to-inside NAT before routing or local delivery. R1 leases directly to PC2 and via R2’s LAN helper to PC3. Syslog uses UDP 514, normally in clear, and R2 targets PC1’s public address. ICMP, TCP 22/23 and UDP 161/162 use the modeled tunnel; HTTP/FTP do not. Keep the course’s explicit defaults (including WAN ACL ordering and automatic inner-header QoS classification).

| `no service dhcp` on R1 still leased to both clients; on R2 it still relayed PC3. | Honor the persisted command on the client-facing listener and on delivery to the relay target. Getting no reply is distinguished from the relay packet getting lost. `service dhcp` restores both roles. [DHCP] |
| Deleting PAT ACL 1 (or leaving just a remark) selected every source by inheriting interface ACL pass-through. A PC2 flow can still succeed without PAT because R2 has a default return route. | PAT/dynamic NAT and rotary NAT require a matching permit ACE; stale dynamic entries no longer stick for absent selectors. Interface ACL pass-through is unchanged. Regression checks actual source/NAT table, not just reachability. [NAT], [ACL] |
| A responder crypto ACL such as `5 deny icmp host 60.50.40.2 host 60.50.50.100` followed by `permit icmp any any` still accepted a PC1→PC3 SA (including reuse after adding the deny). | Check the first live decision for the mirrored packet, as well as the covering permit selector. Reuse and negotiation reject the shadowed permit. Removing the deny permits fresh SAs/counters. Mismatch traces identify both peers without printing their PSKs. [IPsec], [ACL] |
| `qos pre-classify` reset SAs without changing the default exam classifier. Removing explicit serial `clock rate` also silently used `bandwidth` as the physical capacity in the load tool. | Save the local classifier option without resetting SAs, and explain when it has no effect in the training profile. With the override off it changes ESP-vs-inner classification per router. Load uses the effective DCE clock on a cabled serial link; shaping percent still uses bandwidth metadata. [QoS VPN], [Clock], [Scheduling] |
| TCP 22 reported accepted/SSH login without a modeled server. `ssh -p 23` could mistakenly show an IOS Telnet password prompt. | TCP 22 remains an ACL/IPsec/QoS path probe and gets a modeled closed-port response at the IOS endpoint. IOS, Windows and macOS SSH commands distinguish that response and report any open alternate port as TCP reachability only. The IOS `show line` transport settings do not imply an SSH listener. NetLab's Telnet service still uses VTY source and login decisions. [ISR access], [SSH] |
| `no logging trap` reset to severity 6 and `no logging on` was display-only. This follows documented classic autonomous IOS behavior; some Cisco command references describe the `no logging trap` form as reverting to default severity (see [Logging variants]), so do not present this as universal or bench-verified. ## Cross-module integration

- **Syslog:** `show logging` and grading both use `syslogBlockReason`. The screen separates retained local logs from modeled remote dispatch and collection counters; the grader reports global disablement, remote disablement, severity filtering and delivery failures separately.
- **VTY:** On both routers, use a real idle TCP probe for the NAT-visible PC1 source, then apply the same Telnet decision to every enabled VTY range independent of occupancy. Test for source leaks even in ranges that are not first. A broken login (for example, `line vty 5 14` with `login` but no password) fails. The case requires PC1-only access, not a password, so `no login` with the right source restriction still meets task 11. The focused lab explicitly asks for a line password and checks it on every Telnet-enabled range. See [practice grading](final-grading.md).
- **UI terminology:** Label SSH as a TCP 22 path probe, ESP as modeled traffic, and QoS Load as an estimated rate share, not packets actually queued or dropped. The course’s default `qos pre-classify` no-op is intentional, not a requirement to grade by presence of that command.

## Limits and verification

IKE/ESP are synthetic packet objects and SA/counter state, with no ciphers, authentication exchanges, anti-replay, wire capture or timing. ESP reachability is checked during first negotiation as a teaching shortcut. Proxy-selector coverage is simplified; an ordered deny matching the triggering flow is respected, but arbitrary ACL-to-selector math is not emulated. QoS counts classifications and estimates congestion; ordinary sends do not implement a scheduler, shaping delays or policer drops. For Ethernet, the load estimator uses the nominal speed of the modeled port (1 Gb/s by default) and caps it by forced speed settings at either cable end. This is not PHY negotiation, a duplex-mismatch model or measured throughput. Interface `bandwidth` still supplies the MQC percentage reference rate, not physical capacity. The estimator caps the configured shaper by the nominal physical rate, including the 128000/125000 serial clock distinction. DHCP lease aging, full SNMP MIB/version behavior and inform delivery are out of scope. The integrated release supports host filters for modeled link and config traps; see [final notification audit](final-notifications.md).

`node --test tests/sim/forwarding-fidelity.test.ts` exercises CLI → modeled packet delivery, counters, or protocol state. `node --test tests/scenarios/mgmt.test.ts tests/sim/variants.test.ts tests/cli/execnet-ping.test.ts tests/cli/show-variants.test.ts tests/pc/{windows,macos}.test.ts` covers per-range VTY policy and login, syslog diagnoses, Ethernet/serial QoS rates, and TCP 22/23 wrapper text. `tests/lab/reference.e2e.test.ts` and `tests/scenarios/{solutions,mistakes,teacher-solution}.test.ts` verify integrated replay/grading.
