# Course cheat sheet: executed command coverage

**Scope.** This audit covers the unmodified five-page [`course/cheat-sheet.txt`](course/cheat-sheet.txt), sections A–G, including repeated lines, wrapped syntax, commands embedded in notes, and the mirrored-ACL instruction. The fingerprint is checked by the runner. It executes the application's own `inspectLine`, `execLine`, and Ctrl+Z handling on fresh **modeled** Cisco ISR 4331 (IOS XE 17.03.04a) and Catalyst C9300L-24T-4G (17.03.04, Network Advantage classroom profile) sessions. Cisco documents are used independently for hardware expectations; no physical Cisco shell, real network, or on-wire traffic was used. Nothing here implies Cisco image emulation or validation of future releases.

## Run or inspect

```sh
# In the kss-netlab root with Node 24
node scripts/command-coverage.mjs
node scripts/command-coverage.mjs --json --section G
node scripts/command-coverage.mjs --json --device c9300l --line 94
node --test tests/content/coverage.test.ts tests/content/deviceSupport.test.ts
npm run typecheck
# Refresh the checked-in inventories after an intentional audit change
node scripts/command-coverage.mjs --csv > docs/command-coverage.csv
node scripts/generate-device-support.ts
```

The **Commands → Device support** view in Guided and Free modes uses `src/content/deviceSupport.generated.ts`, a compact index generated from the executed audit. It ships with the app (no runtime fetch), and the freshness test checks it against a new run. Counts are matching probes, not distinct commands. Printed notation is separate from the CLI input and mode used by the probe; if a prerequisite failed, the view reports that blocker rather than implying the target command was run. Exam mode keeps only the paper transcription (with the existing typo corrections), without practice notes, tips or probe examples.

- [CSV inventory](command-coverage.csv): exact source page and line range, paper notation, instantiated sample, selected model and network license profile, starting mode, prerequisites, observed parser and execution status, verdict, and evidence. Filter by section / line / model / verdict in a spreadsheet or from the CLI. The JSON format additionally includes all non-command annotations and cross-references, source checksum, the concrete CLI prerequisite transcript, and raw sample response/notes. `blockedAt` means the required submode cannot be entered; the target subcommand was **not** run in an invented submode.
- [`coverage-cases.ts`](../tests/content/coverage-cases.ts) contains the concrete behavioral checks; [`coverage-fixture.ts`](../tests/content/coverage-fixture.ts) builds the in-memory bench. `fresh` = no links. `wire` = cables and PCs but no IOS link configuration. `linked` = routed links with addresses and no routes beyond connected networks. `routed` = adds mutual reachability via static routes. X is the device under test; P is its ISR peer on serial (X ISR) or Ethernet (X switch). A/B are LAN hosts, C is behind P. Specific cases add CLI prerequisites to both sides. The test treats disagreement with any declared outcome or behavior as a failure, not as an easy pass for an unexpected `unresolved`.
- Source coverage is **149 paper command references** (A: 38, B: 10, C: 16, D: 29, E: 26, F: 6, G: 24). The inventory has **565 model/form probes**, not 565 separate commands or a compatibility percentage. Example splits: all five TCP/UDP port operators in both positions; default and explicit SNMP community access with and without a numbered ACL; SNMP notification/selectors by version and type; old and MQC queueing in their respective modes. It samples argument families and behavior, not every possible address or every release-specific option Cisco offers.

| Label | Meaning |
|---|---|
| Functional | Independent assertion observes intended modeled use: mode transition, password exchange, stateful display, route/reachability, NAT, SA negotiation, a forwarded/denied packet, lease, or receiver delivery. |
| Partial | Meaningful subset or materially inaccurate behavior; the row states the limitation and tests the behavior that does exist. |
| Display-only | Nominal response or configuration survives readback; the underlying feature (debug, menu execution, SA expiry, packet thresholds, etc.) does not run. |
| Unsupported | Lab does not accept the valid form, which is documented on at least one in-scope hardware/license combination. |
| Correct hardware rejection | The model's refusal corresponds to a documented hardware, link-role, interface-mode, or feature restriction. |
| Ill-formed paper notation | An instruction, typo, wrong prompt, uninstantiated token family, or inapplicable combination rather than a valid CLI command. A corrected usable form is tested where applicable. |
| Unresolved | Real hardware availability of an exact form was not established. Model behavior is still recorded, and the audit does not use it to claim real hardware support or lack of support. |

## Findings and what to do next

| Section | What runs | Material limits and recommended action |
|---|---|---|
| A · Setup and routing | Console mode transitions, MOTD and line passwords; operational link and address state; RIP and OSPF install usable routes in the modeled small network; static/default routes forward; CLI ping and traceroute use packets; copy asks for confirmation and saves a snapshot. | `control-z` is a key event, not input text. `logging synchronous` is a saved setting, not an async redraw. `show version` is modeled metadata. `debug ip rip` and `undebug all` do not start/stop any debug job. Serial `clock rate 56000` works on equipped DCE, not DTE/unplugged or Catalyst Ethernet. Catalyst IP address/interface tests use `no switchport` and `ip routing`; an SVI is another real-hardware option. Do not infer protocol timing, license entitlement, or converged production topology from show output. [1–3] |
| B · ACL | Numbered permit/deny, wildcard and host semantics, numeric/keyword protocol values in modeled L4, TCP/UDP port predicates (source, destination, both), numeric/keyword ICMP filtering, direction, counters/logs, VTY source ACL, deny → timeout under `no ip unreachables`. | `[source-port]` and `[dest-port]` are only port predicates on TCP/UDP and need an operator; `established` is TCP-only. Real IOS ACEs check ACK/RST; the model approximates with `tcpSyn`. `redirect` and ICMP `traceroute` parse, but there are no such generated ICMP messages; normal traceroute's TTL-expired packets are not ICMP type 30. GRE config is not a test of GRE data forwarding. If expanding fidelity, model ACK/RST separately and test SYN+ACK, RST, and no-flags. [4] |
| C · NAT | ISR and Network Advantage C9300L: inside-source static (address and TCP port), dynamic address pool, pool PAT and explicit interface PAT, reverse rewrite, live counters/shows, and wildcard clear. ISR additionally runs rotary TCP selection and sticky reverse rewrite. | Catalyst requires `ip routing` and addressed routed front-panel Ethernet, not L2 switchports; the permit-only NAT selector limitation and route-map/Port Channel exclusions are explicit in the 17.3 guide. SVI and exact rotary are **unresolved**, not categorical hardware rejections. ICMP is software-forwarded on hardware; the lab models packet behavior rather than TCAM or punt rates. `debug ip nat` is a stub on both. Section C includes companion cases for the routed interface, TCP port static, and documented/profile boundaries. See [Catalyst NAT evidence and scope](final-catalyst.md). [5–7] |
| D · IPsec | ISR CLI PSK, compatible proposal and transform choices, crypto map and symmetric selectors negotiate modeled SAs, with actual simulated encryption/decryption flags and counters; tunnel vs transport sampled on traffic between endpoints; clear/delete affects subsequent traffic. | SecurityK9 assumed on ISR. RSA choices are stored, but PSK is the only operational authentication. SA lifetimes are stored without expiry or rekey; AH, compression, and null treatment are not wire-emulated. `no crypto ipsec sa` is not the clear command. 17.3 accepts older algorithms; Cisco reports warnings starting in 17.6 and default rejection for listed algorithms on ISR 4000 starting 17.11.1a. This is not a C9300L crypto-map VPN; Cisco's later 9300X implementation is IKEv2/SVTI only. Exact real switch availability of the `show`/`clear` keywords is unresolved, distinct from lack of a usable VPN. Debug stubs give no crypto event stream. [8–9] |
| E · QoS | MQC classes drive classifier outcomes and the fluid congestion model; numeric and percentage priority change the bandwidth result, and class-default fair queueing balances the tested flow rates. | `service_policy` → `service-policy`. `kpbs` is a typo and kbit/s is an argument, not a `kbps` literal. Burst and `queue-limit` are not a packet-level queue/drop simulator. 9300 17.3 documents percent queue-limit units rather than packets; physical-port class maps have one match command and `match-any` ACL matches require a named extended list. Do not pretend router MQC fairness is Catalyst ASIC behavior. `custom-queue-list`, interface WFQ, and `show queueing` are documented removals by XE 3.2S. `priority-group` and the legacy list configuration are deliberately rejected by the model; the exact hidden/removed legacy keywords on these images are unresolved. Don't implement classic PQ/CQ to make this sheet look green; direct learners to MQC and `show policy-map interface`. [10–11] |
| F · DHCP | Local leases reflect mask/prefix/classful default, default gateway and excluded range; remote relay reaches a distinct server; deleting the pool removes bindings and prevents fresh allocation. | Use `network 192.168.40.0 /25` or dotted mask, not a bare `25`. DHCP is model-level allocation/relay, not a timed DHCP protocol capture. [12] |
| G · Aliases, menus and management | `alias exec` in config mode expands to the actual command and `show aliases` lists it; syslog destination/source/severity affect collection; `show logging` distinguishes global `no logging on` from remote-only `no logging trap`; v1/v2c-style community ACL and RO/RW work; MIB views restrict modeled GET/SET (numeric, wildcard, common names, more-specific exclusion); enabled configuration edits and linkUp/linkDown transitions dispatch modeled v1/v2c traps subject to host filters. | The printed `#` is wrong for configuring alias and menu entries. `menu text`/`menu command` save lines but the lab does not invoke `menu NAME`, dispatch selections, enforce EXEC privilege of item actions, or implement `menu-exit`. General IOS/XE documentation describes these features; exact menu availability on the 9300L image remains unverified. SNMP host type filters and v3 security selectors survive re-import/reload; omitted v3 level defaults to `noauth`. A later host command replaces the same IPv4 address and notification kind. SNMPv1 cannot inform (also when version defaults to v1). Valid informs and v3 host entries are **display-only**: no acknowledgement, retry, USM, or delivery. Only UDP/162 IPv4 destinations and `config` / `snmp linkup` / `snmp linkdown` trap events are modeled; no on-wire PDU fidelity, per-interface trap controls, or platform-specific notification catalog. `packetsize`, `ifindex persist`, and `system-shutdown` remain saved only; Catalyst guide documents `snmp ifmib ifindex persist`. See [notification verification and limits](final-notifications.md). [13–17] |
