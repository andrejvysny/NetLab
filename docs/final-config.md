# Configuration and terminal workflow review

Audited the actual workbench components and `Lab` against simulated fixtures only. This is a workflow check, not a test of real routers, PCs, networks, login security, or IOS compatibility.

| Path | Behavior and regression evidence |
| --- | --- |
| **Config file merge/replace** | The same CLI executor now drives actual application and the guide's dry-run. File `!` separators at column zero and explicit global prompts close the previous section; sub-mode prompts must agree with the selected mode. An invalid section header cannot send its children to the last good block. `end` ends the file. The file rejects EXEC actions and unanswered interactive commands; a malformed delimiter reports a line error instead of absorbing the remaining commands or installing the text as a banner. Tested in [`apply.test.ts`](../tests/config/apply.test.ts), including the two course listings, rerender, and reload. |
| **Replacement and startup vs. running** | The old implementation reset the live device before discovering line errors or that the text contained only comments. Replacement now validates on a copy, commits only a nonempty accepted candidate, and never writes startup-config. A merge still keeps accepted lines. Replace and boot use snapshot semantics: a listed interface without `shutdown` starts enabled; an unlisted interface keeps its factory state. An encrypted or clear toy password that resembles a credential-type prefix round-trips. Tests: [`apply.test.ts`](../tests/config/apply.test.ts), [`files.test.ts`](../tests/lab/files.test.ts), and [`guided.test.ts`](../tests/lab/guided.test.ts). |
| **Editor actions** | [`ConfigWindow`](../src/ui/bench/windows/ConfigWindow.tsx) reads the selected device buffer through `LabApi`; a clean editor rereads when the live buffer changes or the cable is reattached, but a dirty draft is preserved. Import replaces only the selected editor buffer after confirmation; an asynchronous file read still belongs to its original tab. `Apply to running config`/`Replace running config` never save NVRAM, including when the Startup tab is the source. `Read from device` is an editor refresh, not a device restart. Both write actions are disabled without a usable console (also checked in `Lab`). To persist a successful change, use the terminal's `copy running-config startup-config` at privileged EXEC and confirm its destination. A failed replacement reports that nothing was committed. These UI bindings were audited in source; the regression suite exercises the backing `Lab` and terminal model, not an automated browser file picker. |
| **Live terminal paste, cable move, and reload** | The terminal sends a live sequence of commands, retaining blank lines such as a destination confirmation and leaving the last unterminated line unsubmitted. It strips a matching copied IOS prompt, stops on a mismatched one, stops on common IOS parse errors and guide denials, and does not send queued input into a password prompt or reload/erase confirmation. It does not auto-enter configuration mode or interpret file `!` separators. Pulling a console cable closes its terminal; moving it does not grant access to the old device. Reconnect/open resumes an idle console session; Telnet closes on reload and returns to the PC prompt. Tested in [`terminal-ui.test.ts`](../tests/lab/terminal-ui.test.ts), [`files.test.ts`](../tests/lab/files.test.ts), and [`console.test.ts`](../tests/lab/console.test.ts). |
| **Accidental credential retention** | Hidden login replies remain non-echoed and are never journaled. Recognized inline IOS password/key/community commands are masked in workbench scrollback, file diagnostics and guide blocks, and are not recallable in lab terminal history. The persisted action journal redacts recognized credential forms (including legacy journal imports); the SNMP pane labels its input as secret, and does not display the trap community column as a log. Unsupported IOS secret hashes and encrypted IKE keys are not treated as usable plain values by these workbench paths. Tested in [`apply.test.ts`](../tests/config/apply.test.ts), [`files.test.ts`](../tests/lab/files.test.ts), [`terminal-ui.test.ts`](../tests/lab/terminal-ui.test.ts), and [`pc.test.ts`](../tests/lab/pc.test.ts). |
| **PC actions** | DHCP client retries track actual Windows `ipconfig` release/renew and macOS `ipconfig set en0 DHCP`, not arbitrary command text containing “release”, “renew”, or “DHCP”. Windows and macOS prompts match the simulated OS shells. SNMP GET remains a check; guided SNMP SET is checked on the receiving IOS device and recorded as a mutation when it changes settings. A PC Terminal tab cannot briefly reuse the previous device's console while its cable target changes. Tested in [`pc.test.ts`](../tests/lab/pc.test.ts) and [`terminal-ui.test.ts`](../tests/lab/terminal-ui.test.ts). |

## Scope and follow-up

- [`config/apply.ts`](../src/engine/config/apply.ts) accepts simulator-rendered snapshots and the supported course grammar. It is not an IOS configuration validator. Inspect the line notes and show output when a command is accepted but not modeled. The file editor is a simulator convenience: the physical PC-to-CON link is mandatory, but a file is a separate configuration session, not the typed authentication dialogue. The report has a deliberate read-only exception to the cable requirement for comparison after grading.
- Configuration, startup text, explicit `show …config` output, device state in full lab saves, and packet simulation data still contain **lab-only** credentials where required to reproduce the exercise. They are not a private format or safe to share with real secrets. Transcript safeguards recognize supported command shapes; raw shell output, freeform text, and credentials entered via custom aliases are not a general redaction guarantee.
- **LabApi/CLI follow-up:** expose a structured CLI outcome and safe echo string (or sensitivity/argument metadata) through `ExecView`. The workbench currently recognizes common rejection text and direct credential syntax; a structured result would let paste stop for every rejection and let custom aliases share the CLI's exact masking rules. Lower-level CLI consumers that bypass `Lab` must handle history masking themselves. `copy startup-config running-config` and reload diagnostics are owned by the CLI: if opening a legacy/third-party saved lab with an unsupported startup line, propagate its per-line diagnostics rather than implying the old text was fully restored.
- Browser interaction smoke check for integration: select Startup → Import → confirm → ensure no device change; apply → confirm startup stays unchanged and running changes; disconnect → ensure actions disable and draft remains; reconnect → read clean buffer; separately save in the terminal and inspect the refreshed startup tab. Run with synthetic lab data.
