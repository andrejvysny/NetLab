# Final audit: student console and CLI

Scope: the simulator’s autonomous ISR4331 and C9300L (Amsterdam 17.3-style profiles), not a live device or IOS image. I exercised the in-memory CLI and the Workbench’s terminal-model contract. No build, publication, or dependency installation was performed.

## Changes and before/after evidence

| Exercise | Before | After |
|---|---|---|
| Login and mode transitions | Both keys already re-prompted at ordinary line login. But console `login local` with no users fell through to EXEC, and removing the line password while `Password:` was pending could silently end login. `enable 1` gave `#`. | Ctrl-C and Ctrl-Z retain username/password challenges. Local login requires a usable account; stale challenges fail closed with a reconnect message. Non-15 `enable` levels are refused explicitly. Console line password and enable password remain separate prompts and input at those prompts is not echoed. |
| Config prompt and `do` | Ctrl-C at an ordinary config prompt dropped to `#`; bare `do` was invalid; `do configure` could start a prompt that later changed mode; `do exit` could close the session. | Ctrl-C cancels input without leaving the config context. Ctrl-Z at the command prompt and `end` return to `#`; `exit` backs up one level. `do` offers EXEC help and is incomplete without a command; mode-changing EXEC commands such as `configure`, `exit` and `disable` are excluded, also through aliases. `do show` keeps the submode and is read-only. |
| Abbreviations and help | `deb crypto i` chose a debug topic by array order; unknown debug topics were accepted. Invalid or partial menu items were saved as opaque lines. | Debug topics and menu forms use the keyword grammar. Ambiguity and missing arguments are reported. Known debug syntax and menu configuration state their limits rather than claiming live debugging or interactive menus. In submodes, help and Tab can also find a global command such as `hostname`. |
| Aliases and `show` filters | `inspectLine` did not recognize `rc \| i ^hostname` for `alias exec rc show running-config`; direct execution stored the expansion in history and `do rc \| i …` failed. Some incomplete filters were merely invalid; a malformed regex silently became a literal search. | Inspection and execution use the same single alias expansion and filter parser. The direct alias and `do` form both yield `hostname R1`, preserve typed history (except credential-bearing commands) and keep the privilege checks of the underlying command. `?`/Tab know the pipe modifiers. A missing modifier or expression is incomplete; an unknown modifier or invalid expression is invalid. Pipes inside actual configuration text/regex alternation are preserved. `section` also includes children of nested headings. |
| Read-only verification | `show ip interface brief` worked at `>` and the configuration views already required `#`. A nonexistent interface in `do   show running-config interface …` or an aliased version could place the caret at a different column from the typed text. | The privilege split is retained on both models and on alias targets. Config views remain read-only, normalize interface numbers, and align caret errors to the actual typed command. |
| Save and other prompts | An arbitrary response to `Destination filename [...]?` could still save to the default filename or merge into running config. Unsupported `clear line` printed `[OK]` without resetting a session. | Copy refuses unsupported destinations without changing the config and reports incomplete startup merges rather than unconditional success. Ctrl-C/Ctrl-Z can cancel pending confirmation/dialog input without confirming. Unsupported clearing, debug settings, RSA generation and terminal width/monitor behavior are disclosed. Genuine IOS secret hashes are not accepted as lab passwords. |
| Paging | CLI session state started at 24 even after explicit `length 7` on console or `length 0` on VTY. | New CLI sessions inherit their line’s explicit `length`; `terminal length` remains session-only and resetting it restores the initial line value in the CLI. The existing browser pager passed an integration test for direct `term len 5`, Enter/Space, Ctrl-C and `terminal length 0`; see the UI limit below. |

## Cisco references and boundaries of the comparison

- [ISR 4000 XE 17 Basic Router Configuration](https://www.cisco.com/c/en/us/td/docs/routers/access/isr4400/software/configuration/xe-17/isr4400-sw-config-xe-17/basic_router_configuration.html): console `enable` → `configure terminal`, `line console 0`, `line vty 0 4`, and line password/login. The default-running-config example shows an older image, so it is not proof of all ISR 4331 17.3 defaults.
- [Catalyst 9300 XE 17.3 CLI reference](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-3/command_reference/b_173_9300_cr/using_the_command_line_interface.html) and [IOS XE 17 CLI fundamentals](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/syst-mgmt/b-system-management/m_cf-cli-basics.html): unique prefixes, `?`/Tab, mode prompts and `exit`/`end`/Ctrl-Z, `configure` source prompt and `--More--` controls. Ctrl-C at an ordinary CLI prompt is modeled here as cancellation of the input buffer; exact behavior in every real terminal/IOS dialog was not verified.
- [Cisco EXEC Commands in Configuration Mode](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/fundamentals/configuration/15mt/fundamentals-15-mt-book/cf-feat-do-cmd.pdf): `do show`/`clear`/`debug` from config modes; `do configure terminal` is expressly excluded. The simulator also excludes other session navigation commands from `do` to keep the current mode/session consistent.
- [Cisco IOS Fundamentals: `alias`](https://www.cisco.com/c/en/us/td/docs/ios/fundamentals/command/reference/cf_book/cf_a1.html): global-configuration command, alias names must be typed in full, options may follow an alias, `show aliases` lists them, and leading whitespace bypasses aliases. [Cisco IOS XE output filtering](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/fundamentals/configuration/xe-16/fundamentals-xe-16-book/cf-cli-search.html): case-sensitive expressions, pipe modifiers, and line/page controls. The parser here uses JavaScript regex syntax, not every IOS regex operator.
- [Catalyst 9300 XE 17.3 configuration files](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-3/configuration_guide/sys_mgmt/b_173_sys_mgmt_9300_cg/managing_configuration_files.html): terminal configuration vs a separate saved copy; `show running-config`/`show startup-config` in the privileged procedure; `copy running-config startup-config` and `system:`/`nvram:` spellings. The simulator's existing NVRAM totals are display estimates, not verified `show startup-config` limits on both platforms; no hardware default was inferred from them.
- [Catalyst 9300 access and privilege levels](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-18/configuration_guide/sec/b_1718_sec_9300_cg/controlling_switch_access_with_passwords_and_privilege_levels.html) and [Cisco Telnet password support note](https://www.cisco.com/c/en/us/support/docs/ios-nx-os-software/ios-software-releases-121-mainline/46960-config-telnet.html): distinct line/enable passwords, local accounts, levels 1/15, and refusal when a login-enabled VTY lacks a password. No claim that every console model/release uses the lab’s behavior for `login` with no password configured.
- [Cisco Fundamentals: line `length`](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/fundamentals/command/Cisco_IOS_Configuration_Fundamentals_Command_Reference/L_through_mode.html): length 0 disables pauses; the generic reference gives 24 by default and distinguishes line configuration from a session-only setting. The lab keeps its 24-line fallback; it does not infer terminal negotiation defaults from this reference.
- [Catalyst 9000 configuration register support note](https://www.cisco.com/c/en/us/support/docs/switches/catalyst-9300-series-switches/216850-configuration-register-equivalent-clis-i.html) and [ISR 4000 XE 17 configuration register](https://www.cisco.com/c/en/us/td/docs/routers/access/isr4400/software/configuration/xe-17/isr4400-sw-config-xe-17/m_configuration-register.html): the traditional command is ineffective on Catalyst 9000; the lab declines it on C9300L and stores the ISR form with a no-boot-effect note. [Catalyst 9300 XE 17.7 release notes](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-7/release_notes/ol-17-7-9300.html) document the newer mandatory setup secret; no assumption is made that the lab’s 17.3-style setup applies to 17.7+ or that ISR 4331 has the same requirement.

## Findings at the first integration checkpoint

The pager, pending-input and safe-echo findings below were subsequently addressed. See [final terminal integration](final-terminal-integration.md) for the release behavior.

- **Workbench paging and pending text (UI / Lab API):** The browser watches the text of directly typed `terminal length` commands; it does not get authoritative `termLength` through `SessionView`/`ExecView`. Verified locally using a cabled console model: define `alias exec lp terminal length 0`, return to EXEC and type `lp`; `show terminal` displays `Length: 0 lines` but the Workbench still pauses. Configured `line length` and reload can likewise disagree with it. Plumb actual state through the Lab API and remove the regex guess in the UI follow-up. The UI can consume `?` during non-secret pending text, and it drops the unfinished input buffer on Ctrl-Z; no character-at-a-time Cisco terminal editor is emulated. `--More--` itself is UI state.
- **Boot and console (world / UI):** Initial setup only supports skip, with no AutoInstall/PnP/strong-secret wizard integration or serial hardware negotiation. `Press RETURN` is informational: a valid command works immediately at the normal prompt. AUX is recognized on the router but not connected/simulated; `logging synchronous` is saved, while the lab queues status logs regardless. The simulated factory configuration has VTY 0–4; the handout’s worked solution configures 0–4 and 5–14. Absolute line numbers and VTY capacity/transport defaults are not claimed for all hardware releases.
- **CLI coverage:** No AAA, SSH server/login, verification against genuine IOS secret hashes, runtime menus, or internal debug stream. The `ssh` command probes TCP 22 (or `-p`) without negotiating SSH. The CLI suppresses credential-setting lines in its history even when invoked by alias; UI/journal masking should share the alias-aware parse rather than rely on visible text or CLI history. The lab models 1/15, one alias expansion, one output filter, and a subset of commands/parameters. `configure` accepts the terminal source only. Generic verification commands outside `showconfig.ts` still use their own caret helper; migrate it to `env.screenColumn()` if exact `do`/alias indentation is needed everywhere. Release-specific side effects of `reload`/`clear`/`terminal monitor` are not claimed.
- **Sheet, renderer/apply, forwarding:** Unchanged by this audit. `alias exec` and `menu` are entered in global configuration mode even if the printed sheet shows `Router#`. Related config-file reporting, workbench presentation, runtime flows and guides have independent owners.

The pager, pending-input, safe echo and startup diagnostics follow-up is in [Terminal integration](final-terminal-integration.md).
