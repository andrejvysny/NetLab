# NetLab practice grading: Prípadová štúdia 2026

The assignment and worked solution are in [the course handout](course/case-study-2026.sk.txt) and [course overview](COURSE.md). The real practical is about three hours and worth 18 points. **The weights below are NetLab practice points, not the instructor’s marking scheme or a prediction of an exam mark.** The full case retains the handout’s 13 numbers: task **9** (host-to-host Windows IPsec) is crossed out and has no requirement, guide step, or points. The examples show one route through the work; grading does not depend on when or in which order you type commands in Exam or Free mode. Guided mode teaches one order and only unlocks the next step after observed progress.

Partial credit within a requirement is proportional to the supported checks, rounded to one decimal. A negative check can wait for a positive control; broken routing, an unavailable service, or a missing lease is not evidence of a restriction. Examples use R2’s view of PC1 after R1’s static NAT; R1 itself sees PC1’s private address. Effective management source permissions are inspected independent of whether other stations happen to be on or connected. Named/numbered ACLs, equivalent first-match permit/deny rules, alternative valid addressing where the worksheet leaves it open, a single working DHCP server on either router in the full case, alternate ports and DCE orientation, and effective absolute/percentage shapers are not distinguished by score.

The task 11 worked solution uses `password cisco` and `login` on both VTY ranges on each router. NetLab keeps that example but the case assignment itself only requires PC1-only Telnet access. Case grading accepts `login local` with a usable local user, a different working line password, or `no login` with the required source restriction. It rejects a configured login that cannot complete (missing line password or no local users). The separate **Telnet, SNMP and syslog** lab explicitly requires the assigned line password and login on every Telnet-enabled range. This is a distinction between scenario requirements, not Guided/Exam/Free mode or advice to use Telnet or disable authentication outside the exercise.

Task 13 requires the destination and source, not a particular trap threshold; the focused lab also tests debugging-level delivery. A disabled global logging switch, disabled remote syslog, a filtered severity and failed delivery are separate diagnoses.

## Simulator versus hardware

- **Course profile** (`qosClassifiesInnerHeader: true`): follows the classroom listing and classifies the inner header automatically. Its legacy IKE settings are also usable on this simulated image. This is a teaching simplification, not an IOS XE guarantee. `qosClassifiesInnerHeader: false` tests the ESP-only behavior: the very same config fails QoS until the **active** crypto map on each sender has `qos pre-classify` or equivalent modeled classification that gives the required treatment. Merely matching ESP cannot distinguish ICMP from the guaranteed services. The example includes `qos pre-classify` and uses stronger IKE parameters. Module/license, IOS XE version, and CLI support are separate hardware questions.
- Serial clock is supplied by whichever router actually holds DCE. If the hardware only offers the documented 125 kbit/s alternative for 128, NetLab accepts it and expects 95% of the actual accepted clock (118.75 kbit/s rather than 121.6 kbit/s). If using a percentage shaper, set the interface's reference `bandwidth` to the accepted rate, or use the equivalent absolute shaper. The model example is nominal 128 kbit/s. Ethernet variants do **not** require a fictitious `clock rate` or PHY speed; their slow rate is a reference for shaping, not the Ethernet line rate. `bandwidth` is metadata for percentage calculations, not a physical rate control.
- Per-packet QoS checks are classification and effective policy checks; they are not measurements of real WAN throughput, encryption overhead, or an IOS XE queue scheduler. MQC `fair-queue` is the simulation’s stand-in for the task’s WFQ. Protocol coverage uses representative IPv4 traffic, not a proof for every possible IP header, fragmentation state, or classifier. Scope checks on source ACLs respect first-match ordering and wildcard masks for the modeled headers; they are not a substitute for a full security audit. The examples use SNMP communities and Telnet for the course exercise only.
- Test traffic runs on copies with an idle VTY and clean NAT/negotiation state. Grading does not add live leases, write live MIBs, keep sessions open, change profiles, or alter the student’s journal. Hardware profiles are external to student configuration; compare only against the configured profile.
